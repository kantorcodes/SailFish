# 旗鱼想法本

点子先记在这里。想法会很多，一律记下，不筛。这不是待办清单：想法是还没验证的东西，没有「必须做完」的意思。讨论之后可能觉得不要做，也可能真的就做了；做了也可能不太满意，先搁在分支里，暂时不上线。想法要花时间才变成方案，方案要花时间才变成功能。这个本子就是那段时间差的收容所。

翻的时候看四堆：**未完成**、**已完成**、**做成了但不上线**、**不做了**。一条后来怎样了，对照提交和还没合进来的分支就能看出来——上线了就挪到已完成并挂提交；做了但不满意、还在分支里，挪到「做成了但不上线」并挂分支名；讨论后决定不做，挪到不做了，留一句为什么。**做完了就改本子**，不等下次才补。

已经写成独立方案、还没勾完的，仍在 `docs/plans/`（文件名没有 `done-` 前缀的就是）。那些不必再抄一遍到这里。

### 想法 · Agent 按阶段自主压缩，平衡缓存和 token

- **记下**：2026-09-14
- **想法**：上下文还没到上限，但前面已经做完一大段、后面不再需要那些原文时，继续靠缓存拖着整段是浪费。希望调整说明和工具，让它在合适的时候自己压，不必等人 `/compact` 或等窗口快满。平衡点跟厂商价格有关，还没想清楚划算点在哪。2026-09-14 补：后面若还要做很复杂、会走很多轮的事，前面用不上的 token 就该先压——虽然会破缓存，但后面每一轮都瘦一圈，往往更划算。经济性要让它自己会掂量，别只等窗口满。觉得现在的模型已经够聪明。
- **方案**：有方案。`docs/plans/done-2026-09-14-agent-economic-compact-design.md`。查看和压缩合成一扇门，从一开始就在；说明里写清这本账。价目公式不做。
- **已落实**：查看和压缩是同一扇门，从一开始就在。设置 → 通用里四档主动压缩（不主动压缩 / 较少 / 适中 / 较多），只改它看见的说明。快满和人手动压缩不受影响。`2d31bfb3`
